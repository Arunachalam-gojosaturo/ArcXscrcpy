# ARC-LINK Troubleshooting Guide

This guide covers all known edge cases, errors, and mitigation procedures.

| Symptom / Error | Root Cause | Diagnosis Command | Exact Resolution |
|---|---|---|---|
| **`error: device unauthorized`** | Laptop's RSA public key is not registered in `/data/misc/adb/adb_keys` on the phone. | `adb -s <ip>:<port> get-state` returns `unauthorized` | Re-run one-time pairing: On laptop run `adb pair <ip>:<pair_port> <code>` while phone screen is visible, or connect via USB cable once and check "Always allow from this computer". |
| **`error: device offline`** | TCP socket opened but ADB daemon handshaking hung or stalled. | `adb devices` shows `<ip>:<port> offline` | In desktop UI click **DISCONNECT**, wait 3 seconds, and click **CONNECT PHONE**. Alternatively, toggle laptop Wi-Fi OFF and ON to force fresh discovery. |
| **Port changed after reboot** | Android 11+ uses dynamic randomized ports (between 37000 and 44000) for Wireless Debugging on every boot. | Phone port does not match cached endpoint | Normal behavior. ARC-LINK solves this automatically via UDP Knock on port 9099 and mDNS (`_adb-tls-connect._tcp`), which resolves the current random port. |
| **Hotspot host blocks Wireless Debugging** | Some Android vendor kernels block loopback/self-directed traffic between AP interface and device local services. | Knock succeeds but `adb connect 192.168.43.1:PORT` times out | In `~/.config/arc-link/config.toml`, set `fallback_to_mdns = true`. Some OEMs allow mDNS discovery while dropping direct TCP SYNs on the gateway IP. |
| **ADB key mismatch** | `~/.android/adbkey` on Arch Linux was regenerated or wiped. | `adb pair` succeeds but `adb connect` remains unauthorized | Copy `~/.android/adbkey.pub` from laptop to phone's trusted storage via USB, or re-pair via `adb pair` using the Pairing Dialog (Ctrl+P). |
| **OEM Battery Killer (Xiaomi / Samsung / Huawei)** | Aggressive vendor task killer kills `ArcLinkService` 10 minutes after screen off. | `adb shell dumpsys activity services com.arcx.arclink` returns empty | Run `adb shell dumpsys deviceidle whitelist +com.arcx.arclink` and `adb shell am set-standby-bucket com.arcx.arclink active`. On MIUI/HyperOS, enable "Autostart" in app settings. |
| **Wireless Debugging OFF until First Unlock (FBE)** | File-Based Encryption protects user credential storage until the first PIN/password unlock after reboot. | Knock arrives but `WRITE_SECURE_SETTINGS` does not start ADB daemon | Enable **Direct Boot Aware** mode (already configured in ARC-LINK manifest). If phone has a startup PIN, swipe/enter PIN blind on broken digitizer or use OTG keyboard once. |
| **`scrcpy not found`** | `scrcpy` binary is not in `$PATH`. | `which scrcpy` returns error code 1 | Run `sudo pacman -S scrcpy` on Arch Linux. Ensure scrcpy package is up to date (v2.0+ recommended). |
| **Sniffer permission denied** | Polkit policy not installed or user cancelled `pkexec` password prompt. | `Sniffer stopped: execution error` in log console | Ensure `/usr/share/polkit-1/actions/org.arclink.sniffer.policy` is installed and `/usr/lib/arc-link/arc-link-sniffer` has executable permissions (`chmod 755`). |
